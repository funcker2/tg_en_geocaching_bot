# Геокешинг-бот v2 — дизайн

Дата: 2026-10-27

## Зачем

v1 — «свободная» игра: игрок видит расстояния до всех точек сразу, едет к любой,
активирует по геолокации и получает фото-фрагмент. v2 — гонка на время по
единому маршруту: команды на машинах проходят точки строго по порядку, на каждой
точке снимают физический код, бот выдаёт следующую точку. После последней точки
бот показывает текстом, где лежит финальный код. Побеждает быстрейшая команда.

## Цели

- Последовательная выдача точек, переход только по верному коду.
- Командная игра: общий прогресс на команду, вход по паролю команды.
- Удобная навигация из машины: расстояние до текущей точки обновляется само.
- Защита от пересылки кодов: код принимается только рядом с точкой.
- Таблица результатов по времени для админа.

## Не цели

- Фото-фрагменты, кулдауны, свободный выбор точек (это v1).
- Разные маршруты для разных команд.
- Мультиязычность: v2 только на русском.
- Учёт финального кода в боте: финальный код ищут физически, бот его не принимает.

## Анти-цели (провал, даже если «работает»)

- Игрок, стоящий на точке, получает «вы слишком далеко» из-за погрешности GPS.
- Водителю приходится постоянно тапать телефон, чтобы видеть расстояние.
- Одна команда может пройти точку, просто получив код от другой команды.
- Участники одной команды видят разную текущую точку.

## Структура репозитория

Репозиторий `tg_en_geocaching_bot` разносится на две папки:

- `v1/` — текущий бот как есть (перед переносом подтянуть 2 коммита из
  `origin/main`: live-location и точность GPS).
- `v2/` — новый бот, самостоятельный: свой `app.py`, `Dockerfile`,
  `docker-compose.yml`, `.env`, `data/`.

Стек тот же: Python 3.12, aiogram 3, aiosqlite, Docker. *(Решение Claude.)*
**Деплой (решено пользователем):** v2 запускается **вместо** v1 с тем же
`BOT_TOKEN` — тот же Telegram-бот, токен не меняется. v1 на сервере
останавливается (не удаляется, чтобы можно было вернуть). У v2 своя база в
`v2/data/` — схема несовместима с v1, данные v1 не трогаются.
Из v1 переиспользуется копированием: `utils/geo.py` (haversine, fuse_fix),
логика обработки live-location (редактирование одного сообщения с троттлингом).

## Ход игры (решено с пользователем)

1. Игрок жмёт /start → бот просит пароль команды.
2. Верный пароль → игрок привязан к команде. Сколько угодно человек на один пароль.
3. **Старт команды** — момент, когда первый участник команды ввёл пароль.
   С этого момента команде выдана точка №1.
4. Бот предлагает включить трансляцию геопозиции (live location) и показывает
   расстояние до **текущей** точки команды. Другие точки не показываются.
5. Пока идёт трансляция, сообщение с расстоянием обновляется само (редактирование
   одного сообщения). Разовая отправка геопозиции тоже работает — как запасной вариант.
6. На точке игроки находят код и пишут его боту текстом.
7. Код принимается, только если отправитель находится в **радиусе 15 м** от точки
   по своей последней геопозиции.
8. Верный код → точка засчитана с отметкой времени; **всем участникам команды**
   приходит сообщение с новой текущей точкой.
9. После кода последней точки команда финиширует (время финиша = время ввода
   кода последней точки), всем участникам приходит **текст-подсказка**, где
   лежит финальный код.

### Детали, решённые Claude

- **Радиус**: 15 м + поправка на точность, которую сообщает телефон
  (`horizontal_accuracy`), с потолком поправки 10 м. Итого не больше 25 м.
  Без поправки стоящий на точке игрок при погрешности 10 м получает отказ.
- **Свежесть геопозиции**: если последняя координата отправителя старше 2 минут,
  код не проверяется — бот просит обновить гео.
- **Геопозиция личная**: каждый участник видит расстояние от своей позиции;
  код проверяется по позиции того, кто его ввёл. Трансляцию может включить
  любой участник или несколько.
- **Направление**: рядом с расстоянием показывается стрелка и сторона света
  («↗ 340 м, СВ») — с машины это удобнее голого расстояния.
- **Сравнение кода**: без учёта регистра, лишних пробелов, ё/е.
- **Неверный код**: «Код неверный», без штрафов. Код верный, но далеко:
  «Вы далеко от точки (N м), подъезжайте ближе».
- **Неверный пароль**: «Пароль не подходит», без блокировок.
- **После финиша**: бот на сообщения отвечает подсказкой финала и временем команды.
- **Гонки**: два участника одновременно ввели верный код → засчитывается один раз
  (проверка «текущая точка команды всё ещё та же» внутри транзакции).
- Игрок может выйти из команды командой /logout и войти в другую по паролю.
- **Нет геопозиции**: код не проверяется, бот просит прислать гео. Если телефон
  не сообщил `horizontal_accuracy`, поправка к радиусу = 0 (строго 15 м).
- **Правка маршрута во время игры**: текущая точка команды хранится как номер
  по порядку (`position`); удалённая/переставленная точка сдвигает маршрут,
  админ предупреждён.
- **Время**: хранится в UTC, показывается в часовом поясе из `TZ` в `.env`
  (по умолчанию `Europe/Sofia`).
- **Тестирование админом**: тестовая команда с флагом «тест», не попадает в
  таблицу результатов, её прогресс сбрасывается отдельно от общего сброса.

## Админка (только русский; доступ по `ADMIN_IDS`)

- **Точки маршрута**: добавить (название → гео-пин → код), изменить любое поле,
  удалить, поменять порядок (вверх/вниз). Показ точки как её видит игрок.
- **Финальная подсказка**: один текст на игру, редактируется в админке.
- **Команды**: «Создать N команд» — бот сам генерирует названия («Команда 1…N»)
  и пароли, удобные для диктовки (слово + две цифры, например `тигр-42`,
  уникальные). Выдаёт список «команда — пароль» одним сообщением для рассылки.
  Можно переименовать команду, удалить, добавить ещё.
- **Таблица результатов**: команда, старт, время каждой точки, финиш, итог
  (финиш − старт). Сортировка: финишировавшие по итогу, затем остальные по
  числу взятых точек и времени последней.
- **Сброс игры**: обнулить прогресс и старт всех команд; точки, команды, пароли
  остаются. С подтверждением.
- **Играть как игрок**: админ может войти в команду по паролю для проверки.
- Изменение маршрута во время игры не запрещено, но админ видит предупреждение,
  если есть стартовавшие команды.

## Данные (ориентир, детали — за строителем)

- `points(id, position, label, lat, lon, code)`
- `teams(id, name, password, started_at, finished_at, current_position)`
- `members(user_id, team_id, last_lat, last_lon, last_accuracy, last_loc_at)`
- `team_points(team_id, point_id, taken_at, taken_by)`
- `settings(key, value)` — `final_hint`.

## Оставлено строителю

- Тексты сообщений, раскладка клавиатур, формат таблицы результатов.
- Словарь для паролей, точная формула стрелки направления.
- Интервал троттлинга редактирования (в v1 — 4 с).
- Тесты: на чистую логику (проверка кода, радиус, гонки, порядок точек,
  сортировка результатов).
